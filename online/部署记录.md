## 二、两个必须知道的坑（都已解决）

### 1. 函数第一次创建失败：Timeout(s)=3

`tcb fn deploy` 推断出的默认超时是 **3 秒**，而云上安装 `wx-server-sdk` 装不完 → 函数记录建出来但状态 `Creation failed`、代码 0 字节、`Code size (B) = 0`。

**修复**：在 `online/cloudbaserc.json` 里写 `functions[].timeout: 20`（仓库 README 也要求 ≥10 秒），再 deploy 即成功。

### 2. PowerShell 会剥掉传给原生程序的内层双引号

```powershell
node probe.js --command '[{"TableName":"x","Command":"{\"find\":\"x\"}"}]'
# 实际到达进程的 argv：
# ["--command","[{TableName:x,Command:{\"find\":\"x\"}}]"]   ← 结构引号全没了，JSON 非法
```

影响一切需要传 JSON 的 CLI（`tcb db nosql execute --command`、`tcb fn invoke --params`）。

**可用解法**：JSON 的**结构引号保持裸 `"`**（被剥掉后恰好还是合法 JSON），
**字符串值内部**的引号写成 `\u0022`（能存活，且 `JSON.parse` 会解码回真引号）。
再配一个 Node 包装器用 `spawnSync` + 精确 argv 数组调用 CLI：

```powershell
node tcb-run.js fn deploy ...          # 见工作区的 tcb-run.js
node tcb-e2e.js                        # 端到端调用 flyingRoom
```

> 注意：`@cloudbase/manager-node` 未随 CLI 安装，无法直接 `require` 建集合；
> `tcb db nosql execute` 的实现参数腾讯侧仍返回「Check request parameter fail」，
> 所以建集合走的是**临时云函数** `zzBootstrap`（已删除，云上与本地都不残留）。
